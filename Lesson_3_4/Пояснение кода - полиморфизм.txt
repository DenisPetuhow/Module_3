### 1. Почему Figure(const std::string& name) : name(name) {}

В С++ обычно поля объектов инициализируются через так называемый **initializer list** в конструкторе.  
Вот это место кода:

```cpp
Figure(const std::string& name) : name(name) {}
```

- `const std::string& name` — это параметр конструктора, передаем **ссылку на строку** (а не сам объект string).
- Ссылки (в отличие от передачи копии) используются, чтобы избежать лишнего копирования строки, что может быть ресурсоёмко, особенно если строки большие.
- `: name(name)` — запись называется **initializer list**. Она непосредственно инициализирует поле `name` значением, пришедшим параметром.  
- То есть для поля класса `Figure` (protected std::string name), сразу в момент создания объекта (`Figure` или наследника) инициализируем это поле указанной строкой.

Почему передаём **адрес** (а точнее, ссылку)?  
Потому что по конвенции в C++ при передаче больших или сложных объектов (например, строки), использующих внутреннюю динамическую память, выгоднее передавать по ссылке на константу `const T&`, чтобы ускорить и не делать лишние копии.

### 2. : Figure("Треугольник"), a(a), b(b), c(c), A(A), B(B), C(C)

Пример из класса `Triangle`:

```cpp
Triangle(int a, int b, int c, int A, int B, int C)
    : Figure("Треугольник"), a(a), b(b), c(c), A(A), B(B), C(C) {}
```

- `: Figure("Треугольник")` — В этом месте вызывается конструктор базового класса Figure, передавая ему строку "Треугольник". Это нужно, чтобы поле `name` базового класса инициализировать этим значением.
- Далее идут `a(a), b(b)...` — инициализация собственных полей.
- Таким образом, при создании объекта любого класса-наследника от Figure, можно сразу задать имя фигуры для базового класса.

### 3. this->name = "Прямоугольный треугольник";

В производном (дочернем) классе `RightTriangle` конструктор выглядит так:

```cpp
RightTriangle(int a, int b, int c, int A, int B)
    : Triangle(a, b, c, A, B, 90) {
    this->name = "Прямоугольный треугольник";
}
```

- Сначала вызывается конструктор базового класса Figure строкой "Треугольник" (через инициализацию Triagle).
- Затем в теле конструктора мы явно меняем значение поля `name` на `"Прямоугольный треугольник"`.
- Это сделано потому, что иногда хочется задать в базовом классе какое-то дефолтное имя (например, просто "Треугольник"), а у наследников уже прописать своё ("Прямоугольный треугольник", "Равносторонний треугольник" и т.д.).
- В принципе, можно было бы сразу при инициализации передавать нужную строку в конструктор базового класса (через Figure), но вы применили второй вариант.

### 4. Принцип полиморфизма в этом коде

Полиморфизм — один из фундаментальных принципов ООП, который позволяет рассматривать объекты классов-потомков как объекты базового класса и использовать их "по базовому интерфейсу".

В вашем коде:

- Базовый класс `Figure` объявляет виртуальные методы print_sides и print_angles (а также виртуальный деструктор).
- Этим наследники сообщают компилятору: если вы имеете указатель или ссылку на базовый класс Figure, но передаете в неё объект-наследник (например, Triangle, Rectangle и т.п.), то при вызове виртуального метода будет вызвана именно реализация из класса-наследника, а не просто заглушка из Figure.
- Это хорошо показано в функции `print_info(Figure* figure)`

```cpp
void print_info(Figure* figure) {
    std::cout << figure->get_name() << ":" << std::endl;
    figure->print_sides();
    figure->print_angles();
    std::cout << std::endl;
}
```
- С помощью **одной функции** можно обрабатывать любые фигуры, не зная их конкретный тип — главное, что они наследники Figure.
- Благодаря ключевому слову `virtual` в Figure, реально вызывается именно нужная реализация (например, Triangle::print_sides или Square::print_sides), даже если вы туда передали Figure*.

**Итог:**  
Благодаря полиморфизму можно писать универсальный код для обработки целых семейств объектов (фигур) через указатели/ссылки на базовый класс.
